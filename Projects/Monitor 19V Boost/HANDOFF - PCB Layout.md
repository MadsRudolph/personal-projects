## Hard rules for any layout of this board

**Process:** single-sided, THT only, copper on **B.Cu**, isolation-milled with
an 0.8 mm end mill; laser only for silkscreen. Mill envelope 203 x 152 mm.

**Rules (in `monitor-boost.kicad_pro` + `monitor-boost.kicad_dru`):**

| | track | clearance |
|---|---|---|
| Default | 1.0 mm | 0.85 mm |
| Power (+12V, GND, /SW, /VOUT, /CS) | 1.5 mm | 0.85 mm |

- 0.85 mm is the mill floor; nothing may be closer. The only exception
  (`.kicad_dru`) is pad-to-pad inside one transistor (Q1..Q3) at 0.84 mm.
- **Q2/Q3 must use `energy_system:TO-126-3_Vertical_P2.54_LaserPads`** (leads
  bent out to 2.54 mm). The skill's stock `TO-126-3_Vertical_LaserPads` is
  2.28 mm pitch -> 0.58 mm between pads, which the 0.8 mm tool cannot cut.
- 1.5 mm cannot enter the middle pin of a TO-220 at 0.85 mm clearance (2.54
  pitch, 1.7 mm pads): neck down to <= 1.6 mm at Q1's drain, or reach it from
  a pour.
- Current: input/inductor 5.6 A RMS, switch peaks 6.7 A, output 3 A. On 1 oz
  copper that is ~3.2 mm of track at 10 C rise -- use pours for +12V, SW,
  VOUT and GND rather than 1.5 mm tracks where the full current flows.

**Ground topology -- the part that is easy to get wrong:**

1. **Hot loop small and solid:** Q1 drain -> D1 -> C4..C6 -> GND -> shunt
   (R1||R2) -> Q1 source. The GND between C4..C6 minus and the shunt bottom
   must be copper with no track cutting through it.
2. **Input loop:** C1/C2 minus -> GND -> shunt bottom must also be solid.
   On a TO-220 the gate pin sits next to the drain, so the gate line starts
   inside the input loop and has to cross its ground return. The Linux layout
   solves this by letting **component bodies** cross it: R4 (gate resistor)
   and R6 (+12V -> VCC_F) straddle a protected GND strip. Any other solution
   is fine as long as no *track* splits C_in minus from the shunt bottom.
3. **Star point:** U1 pin 8 (GND), CL- (pin 5), R11, R7, C12 return to the
   shunt's ground end, not along the power return.
4. **CS** is a Kelvin tap from the top of the shunt to R14; keep it apart
   from the power current. A wire link is acceptable for it (low current).
5. **Feedback:** take VOUT for R10/R12 at the output caps, route away from SW
   and L1.
6. **SW node** as small as possible (it is the antenna): L1 pad 2, Q1 drain,
   D1 anode.

**Heatsinks:** Q1 (~1.1 W) and D1 (~2.6 W) need TO-220 heatsinks; both tabs
are live (drain = SW, cathode = VOUT) -- separate heatsinks, or one with mica +
bushings from the shop.

## Reviewing a layout (what to check, in order)

1. `git pull`, then open the project fresh (close KiCad first -- a stale
   session reports stale ERC/DRC).
2. **Netlist unchanged:** Update PCB from Schematic should report no changes
   other than footprints. If the schematic was touched, stop.
3. **DRC with the project rules:** Inspect -> Design Rules Checker, all
   severities. Expect only silkscreen overlaps and the documented TO-220/126
   exception. Check that Board Setup -> Net Classes still says 0.85 / 1.0 /
   1.5 -- see "Traps" below.
4. **Connectivity:** 0 unconnected; count F.Cu segments (each F.Cu run is a
   wire link to solder -- say how many and where).
5. **Ground topology:** walk rules 1-6 above on the copper view. Specifically
   look for any track crossing between C_in minus / C_out minus and the
   shunt's GND pad, and for GND pour islands (Edit -> Fill all zones, then
   look for isolated GND copper).
6. **Pads vs mill:** every pad-to-pad gap between different nets >= 0.85 mm,
   no footprint with gaps < 0.8 mm (the TO-126 trap).
7. **Current paths:** widths on the hot loop and input path per the table.
8. **Mechanical:** heatsink room behind Q1/D1 tabs, toroid body clear of
   other parts, terminals J1 (12 V in) and J2 (19 V out) at board edges.

## Traps found so far

- **`pcbnew.SaveBoard` from a script rewrites the sibling `.kicad_pro` with
  0.2 mm default netclasses**, so a later DRC silently passes. After any
  scripted save, check the netclasses (or `git diff monitor-boost.kicad_pro`).
- **FreeRouting 1.9.0 never finishes if the board already has any pre-routed
  track** (fixed or protected). Use a copper zone for anything you want fixed,
  and close leftovers after routing.
- The stock-derived TO-126 LaserPads footprint (2.28 mm) cannot be milled --
  see above.
- The Linux-only helpers (`kicad/tools/kpy.py`, the Python 3.14 pcbnew patch)
  are not needed on Windows; use KiCad's own `python.exe`. `export_production.sh`
  has a PowerShell twin in the kicad-laser-pcb skill (`export_production.ps1`).

1. DRC clean (as above), then export: Gerbers (F.Cu, B.Cu, Edge.Cuts, masks,
   F.Silkscreen, F.Fab) + Excellon drill, silkscreen DXF for the laser --
   the skill's `export_production.ps1` does all of it.
2. Update `README.md` ("The board" section): wire-link count and where,
   any rule exceptions, and the render (`kicad/monitor-boost-pcb.png`).
3. Commit (no AI attribution trailers -- CLAUDE.md) and push.
4. Then: wind and measure the toroid (README "The inductor"), bring-up per
